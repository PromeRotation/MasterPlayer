# 录制回放 v2

新录制使用 `.mpreplay.jsonl`，UTF-8 无 BOM。第一行为 `ReplayHeader`，`v=2`；仍支持旧版 `v=1`。文件中只保存数据，不序列化 PR 的 Raw 运行时对象图。

## 对象快照与事件

首条对象快照必须在 `t=0`，`kind="WorldFrame"`、`data.Full=true`。录制器在主线程每0.1秒、每条保留事件写入前以及停止时采样当前已加载对象；后续帧只写发生变化的完整对象记录及 `Removed` ID。区域变化产生新的完整帧。对象不在当前对象表里即从录制世界移除，不能代表服务器上所有未加载的对象。

| 数据 | 字段或内容 |
|---|---|
| 身份 | Id、EntityId、GameObjectId、Oid、NameId、名字、种类／子种类、OwnerId |
| 空间 | Position（XYZ）、普通Rotation、HitboxRadius |
| 战斗 | Dead、Targetable、InCombat、Hostile、TargetId、等级／职业、HP/MP上限与当前值、护盾百分比 |
| 状态 | Statuses：状态ID、Param、来源、UTC到期时间；尚待生效的负持续时间取绝对值，异常大值上限100000秒 |
| 读条 | 动作ID、目标、落点、原生CastRotation、开始／预计判定时间、可打断标志、已见效果标志；NPC预计判定含0.3秒补正 |
| 连线与外观 | 两个原生连线槽中的有效记录（ID／目标／Progress）、EventState、ModelState、两个AnimationState字节 |
| 事件动画 | EventAnimation为完整32位EAnim；未知为null，与EventState分开 |
| 队伍与视角 | LocalPlayerId、TargetId、PR队伍排序Slot／Role／EntityId、本人的LocalTimelineRole |

`Id` 优先有效 EntityId，否则使用 GameObjectId，脚本按该键读取 `ReplayWorld.Actors`。槽位使用 PR `PartyPrioritySlot` 的0到7；四人队为MT/H1/D1/D2对应0/2/4/5，缺员不补猜。本人时间轴职能另存为名字，避免 `TimelineRole.None` 造成枚举数值错位。

录制器从插件初始化开始监听 EAnim，即使尚未开始写文件也缓存已知动画，移除对象或切区时清理。插件加载之前或从未收到的动画无法恢复；不会从一个EventState字节捏造完整EAnim。

事件行沿用 `t/kind/type/data`，CastStart另外写可选的 `packetFacing` 弧度。该值来自PR `StartCastCaptureRaw.PacketFacing`，普通 `SourceRotation` 不能代替。读回后仅为读条创建 `ReplayCastData` 安全标记；旧文件缺失朝向也创建标记，保证 `CastRotation.TryGet` 不回退读取实时FFCS。对象快照中的 `Cast.Rotation` 是采样时的原生锁定朝向，和事件包朝向分别保留。

玩家／玩家召唤物动作、状态和读条**事件**仍按既有规则过滤；对象快照包含这些角色和状态。聊天事件仍不录制。录制文件会包含对象名字和队伍信息。

## 时间、顺序与生命周期

`t` 使用主线程采样／派发时刻相对录制开始的单调不递减秒数，写入精度0.0001秒；事件本身的 `Timestamp` 保留原值，用来补偿派发延迟。相同 `t` 按文件行序回放，事件前采集的帧先应用。各事件和帧之间推进脚本时钟并调用更新，最后推进到当前播放位置；播放帧率和速度不改变已记录项目的顺序。

`CurrentTime = Header.StartedUtc + Clock`。暂停冻结该时钟和脚本更新；Seek销毁脚本及对象世界，从初始帧按序重演。到文件末尾暂停，保留最终场景。Stop撤销录制时钟和实体位置覆盖、清理区域与绘制，下帧恢复实时脚本。刷新脚本先停止回放，再按实际区域恢复；真实切区／死亡／脱战不能清掉回放场景。回放中禁止自动移动，限时区域仍按录制时钟回收。

v2拒绝未知版本、缺少零时刻完整初始快照、损坏JSON或对象数组空元素；未知事件类型跳过并计数。v1仍可读，界面保留“缺少对象状态”提示；不能通过升级读取器补出历史文件未录制的信息。

## 脚本接入

基类和Host均提供 `DateTime CurrentTime` 与 `ReplayWorldState? ReplayWorld`。实时会话的ReplayWorld为null；回放为独立世界，旧文件也返回空的录制世界，不能因其无对象而读取Svc.Objects补齐。使用 `ReplayWorld.HasSnapshot` 判断是否有录制对象数据，使用 `Version` 检测新帧。

首批地城脚本和可视化机制已接入；雷达人物／队伍／目标及SafeZone动态实体绑定读取录制对象。SafeZone相对时间注册与Draw.AddAoe预览使用录制时钟。直接访问Svc.Objects、DateTime.UtcNow的外部脚本仍需改用这两个接口；PR原始Draw.Add／AddBound／AddTether仍按宿主真实时间和实体绑定运行，不属于已适配的回放绘制路径。斗兽棋机制本轮未修改。

## 验证范围

`tests/ReplayWorldRegression.cs` 验证对象／状态／连线／角色／包朝向往返、增量与移除、同时间行序、不同步长重演、暂停、重建、坏文件、旧文件隔离及真实单体目标。实际DLL测试还启动生产地城脚本，验证范围注册、限时回收、跳转、末尾对象帧、实时生命周期隔离、刷新与清理，并令任何实时对象访问和GreenMove调用直接失败。

这些测试不替代游戏内原生采集和网络时序验收；当前客户端对象字段、队伍排序与世界绘制仍需结合新录制和实际战斗检查。
