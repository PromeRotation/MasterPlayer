# 录制回放 v2

新录制使用 `.mpreplay.jsonl`，UTF-8 无 BOM。第一行为 `ReplayHeader`，`v=2`；仍支持旧版 `v=1`。文件中只保存数据，不序列化 PR 的 Raw 运行时对象图。

## 对象快照与事件

角色的可选 `IncomingEffects` 数组记录原生非零 incoming 槽：`Slot`、`GlobalSequence`、`TargetIndex`、`TargetConfirmed`、`Knockback`。`Knockback` 取八个原始效果中类型31–36（击退/吸引）的并集；也记录非击退槽，以便识别槽替换。数组按内容参与对象差分，确认位变化和槽消失均会记录，旧文件缺失字段默认为空。原生脚本按新序列建立最长三秒的待击退状态，同序列仅翻转确认位不续期或清除；槽消失、序列/index替换或超时才清除。该快照用于恢复机制显示尾窗，不执行移动。

首条对象快照必须在 `t=0`，`kind="WorldFrame"`、`data.Full=true`。录制器在主线程每0.1秒、每条保留事件写入前以及停止时采样当前已加载对象；后续帧只写发生变化的完整对象记录及 `Removed` ID。区域变化产生新的完整帧。对象不在当前对象表里即从录制世界移除，不能代表服务器上所有未加载的对象。

| 数据 | 字段或内容 |
|---|---|
| 身份 | Id、EntityId、GameObjectId、Oid、NameId、名字、种类／子种类、OwnerId |
| 空间 | Position（XYZ）、普通Rotation、HitboxRadius |
| 战斗 | Dead、Targetable、InCombat、Hostile、TargetId、等级／职业、HP/MP上限与当前值、护盾百分比 |
| 状态 | Statuses：状态ID、Param、来源、UTC到期时间；尚待生效的负持续时间取绝对值，异常大值上限100000秒 |
| 读条 | 动作ID、目标、落点、原生CastRotation、开始／预计判定时间、可选原始float TotalTime、可打断标志、已见效果标志；NPC预计判定含0.3秒补正 |
| 连线与外观 | 两个原生连线槽中的有效记录（ID／目标／Progress）、EventState、RenderFlags、ModelState、两个AnimationState字节 |
| 事件动画 | EventAnimation为完整32位EAnim；未知为null，与EventState分开 |
| 队伍与视角 | LocalPlayerId、TargetId、PR队伍排序Slot／Role／EntityId、本人的LocalTimelineRole |
| 移动视角 | LegacyMovement 为传统移动模式；CameraAzimuth 为可空相机方位（DirH + π），用于薄冰滑行方向 |
| 任务技能 | DutyActionPlayerId 为充能归属角色；DutyActions 为可空数组，每项含 Slot、ActionId、CurrentCharges、MaxCharges |

`Id` 优先有效 EntityId，否则使用 GameObjectId，脚本按该键读取 `ReplayWorld.Actors`。本队槽位使用 PR `PartyPrioritySlot` 的0到7；四人队为MT/H1/D1/D2对应0/2/4/5，缺员不补猜。普通联盟额外保存8到23槽，按所选Group的AllianceMembers索引固定映射，不压缩空洞；ARR使用ReplayGroup，其他使用MainGroup，四人小组联盟不扩充。无效及重复EntityId过滤，本队优先。旧文件没有联盟成员时不补实时数据。本人时间轴职能另存为名字，避免 `TimelineRole.None` 造成枚举数值错位。

`Cast.TotalTime` 保存客户端原始读条总秒数，不包含NPC的0.3秒预计判定补正；包事件保留原始CastTime。新文件用该float判断真实总长变化，避免从采样开始／结束DateTime反算时产生100ns级噪声而误重启连续机制。旧文件缺失时仍按时间差恢复；狩猎状态变化检测允许1微秒重建误差。该可选字段沿用v2，不改变原读条构造和解构签名。

录制器从插件初始化开始监听 EAnim，即使尚未开始写文件也缓存已知动画，移除对象或切区时清理。插件加载之前或从未收到的动画无法恢复；不会从一个EventState字节捏造完整EAnim。

`RenderFlags` 为可空整型，采样原生 GameObject 字段并参与对象增量比较。Qarn 原生脚本使用平台的 `RenderFlags=0` 识别当前发光平台；旧 v1/v2 文件缺少该字段时保持 null，不把未知平台当作可解除死宣的站位。此可选字段不改变 v2 版本号。

`LegacyMovement` 和 `CameraAzimuth` 是帧级字段，每个增量帧也保留当前值。旧录像缺字段时按标准移动处理；传统移动帧没有有效相机方位时，不用实时相机或角色朝向伪造落点。暂停冻结，Seek 按录制帧恢复这两个值。

`DutyActions` 同样是每个完整/增量帧的当前值；null（含旧录像缺字段）表示未知，空数组表示已知无任务技，不能沿用上一帧的充能。最多采集两个有效任务技槽，读取实际当前/最大储存次数，不能用动作冷却或护盾状态代替。数据仅归属 `DutyActionPlayerId`，ARR不从本机任务技推测观看角色输入，MP回放也不回退读取实时客户端。吉祥天女据此决定是否取元气球，未知时仍显示球但不猜测拿球目标；回放禁止施放任务技。

事件行沿用 `t/kind/type/data`，CastStart另外写可选的 `packetFacing` 弧度。该值来自PR `StartCastCaptureRaw.PacketFacing`，普通 `SourceRotation` 不能代替。读回后仅为读条创建 `ReplayCastData` 安全标记；旧文件缺失朝向也创建标记，保证 `CastRotation.TryGet` 不回退读取实时FFCS。对象快照中的 `Cast.Rotation` 是采样时的原生锁定朝向，和事件包朝向分别保留。

玩家／玩家召唤物动作、状态和读条**事件**仍按既有规则过滤；对象快照包含这些角色和状态。聊天事件仍不录制。录制文件会包含对象名字和队伍信息。

旧式 Director UnionData 事件写为 `kind="LegacyMapEffect"`、`type="MasterPlayer.Scripting.LegacyMapEffectEvent"`，`data` 含 `Sequence`、`Param`、`Data`（byte[]，JSON Base64）及原始 `Timestamp`。它由 MP 的 FFCS `SetDirectorData` 采集，不与普通 MapEffect 混用；读取器只放行这一明确的本地事件类型。该增量沿用 v2，旧读取器跳过未知类型；旧录像缺少此输入时无法重建依赖它的结束条件。

完整效果包另写为 `kind="ActionEffect"`、`type="MasterPlayer.Scripting.NativeActionEffectEvent"`，包含`SourceId`、`ActionId`、`MainTargetId`、`GlobalSequence`、有序`Targets`及UTC `Timestamp`。主目标直接取FFCS `ActionEffectHandler.Header.AnimationTargetId`，目标数组在原生回调内复制，最多32项；不会从PR按目标展开的事件、数组首项或TargetIndex猜主目标。它与PR展开事件并存，消费者按类型选择，不能两路重复计数。沿用v2；旧录像缺少完整包时无法补出主目标，例如Nuckelavee的Torpedo不能靠旧逐目标事件准确结算。

原生效果队列在主线程交付；PR事件回调前先交付捕获时间不晚于该事件的原生包，比较前统一UTC，晚于cutoff的包保留。正常停止及运行组件释放时先排空录制尾包，再释放采集器；切区和进入/退出MP回放清旧epoch，回放期间不接收实时包。开始前旧包及早于录制起点的包不写入，玩家/召唤物来源过滤同样适用。旧运行库桥的回放转换仍有自己的降级边界，不能把MP脚本完整包输入等同于已修复BMR回放主目标推断。

## 时间、顺序与生命周期

`t` 使用主线程采样／派发时刻相对录制开始的单调不递减秒数，写入精度0.0001秒；事件本身的 `Timestamp` 保留原值，用来补偿派发延迟。相同 `t` 按文件行序回放，事件前采集的帧先应用。各事件和帧之间推进脚本时钟并调用更新，最后推进到当前播放位置；播放帧率和速度不改变已记录项目的顺序。

旧事件 JSON 缺少 `Timestamp` 时，读取器仅为该事件补 `Header.StartedUtc.ToUniversalTime() + t`，避免 record 默认值使用加载时系统时间，使时间线和点名预测偏离录制时钟。已有 `Timestamp` 不覆盖；例如行 `t=2`、事件原时间为开始后 1.75 秒，仍保留这 0.25 秒派发延迟。

`CurrentTime = Header.StartedUtc + Clock`。暂停冻结该时钟和脚本更新；Seek销毁脚本及对象世界，从初始帧按序重演。到文件末尾暂停，保留最终场景。Stop撤销录制时钟和实体位置覆盖、清理区域与绘制，下帧恢复实时脚本。刷新脚本先停止回放，再按实际区域恢复；真实切区／死亡／脱战不能清掉回放场景。回放中禁止自动移动，限时区域仍按录制时钟回收。

v2拒绝未知版本、缺少零时刻完整初始快照、损坏JSON或对象数组空元素；未知事件类型跳过并计数。v1仍可读，界面保留“缺少对象状态”提示；不能通过升级读取器补出历史文件未录制的信息。

## 脚本接入

基类和Host均提供 `DateTime CurrentTime` 与 `ReplayWorldState? ReplayWorld`。实时会话的ReplayWorld为null；回放为独立世界，旧文件也返回空的录制世界，不能因其无对象而读取Svc.Objects补齐。使用 `ReplayWorld.HasSnapshot` 判断是否有录制对象数据，使用 `Version` 检测新帧。

首批地城脚本和可视化机制已接入；雷达人物／队伍／目标及SafeZone动态实体绑定读取录制对象。SafeZone相对时间注册与Draw.AddAoe预览使用录制时钟。直接访问Svc.Objects、DateTime.UtcNow的外部脚本仍需改用这两个接口；PR原始Draw.Add／AddBound／AddTether仍按宿主真实时间和实体绑定运行，不属于已适配的回放绘制路径。斗兽棋机制本轮未修改。

## 验证范围

`tests/ReplayWorldRegression.cs` 验证对象／状态／连线／角色／包朝向往返、增量与移除、同时间行序、不同步长重演、暂停、重建、坏文件、旧文件隔离及真实单体目标。实际DLL测试还启动生产地城脚本，验证范围注册、限时回收、跳转、末尾对象帧、实时生命周期隔离、刷新与清理，并令任何实时对象访问和GreenMove调用直接失败。

这些测试不替代游戏内原生采集和网络时序验收；当前客户端对象字段、队伍排序与世界绘制仍需结合新录制和实际战斗检查。
