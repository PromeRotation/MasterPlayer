# BMR → MP 原生脚本迁移

日期：2026-11-23。目标是将副本的机制状态、连续判定、双视图绘制、面向/视线、PR ACR 停手及移动约束迁入 MP。最终脚本继承 `MasterPlayerScript`，通过 MP 门面输出，不在脚本内再创建 `MechanicSession`、包装 `BossModule` 或继续消费 BMR 桥的结果。BMR 源码保留为迁移依据，未完成的内容按现有门控继续运行。

```powershell

python tools/bmr_migration_audit.py --check
```

生成器检查原清单与启动覆盖清单的类型集合、实际生产源码声明及已记录 MP 入口是否存在。也可用 `--runtime-types <JSON数组文件>` 对比新编译运行库反射出的非抽象 BossModule/ZoneModule 类型，排除 DemoModule。本轮实际反射集合与清单 1,214/1,214 一致，无遗漏或额外类型。

## 4. 按副本推进顺序

每批完成“来源与机制表 → MP 实现 → 生产组件离线验证 → 实机验收”。逐副本关闭验收项；没有证据时保留待验，不用模板生成器批量改成已完成。

1. **公共控制与已有脚本复核。** 原33个已有接管类型已全部补齐离线验证；新增40个狩猎后继续剩余803个。共用编译、集中回归，失败场景按筛选重跑。
2. **ARR 地城。** 以 D04Halatali 为首个新增副本，再按目录顺序处理托托拉克、静语庄园及后续地城；普通和困难版、重制版本分别确认。每个副本覆盖全部 BMR Boss 与道中模块。
3. **其余资料片地城。** Heavensward → Stormblood → Shadowbringers → Endwalker → Dawntrail；白山堡已有实现按同一标准复核。顺序按副本元数据和依赖调整，不按模块名字字母排序替代机制分析。
4. **讨伐与团队战。** 普通 → 极/幻 → 普通团队/联盟 → 零式/绝/灭，逐场处理多阶段及共同组件，分支状态不能用估计时长跳过真实事件。
5. **多变/异闻、寻宝和深层迷宫。** 深宫区分楼层、道中和 Boss；朝圣路普通楼层、死宫其他楼层、天宫和正统优雷卡仍是独立任务。
6. **大规模探索、任务战与其他内容。** 保留 97 个任务区域模块的审查范围；原运行库任务自动导航恒不输出的路径也须记录，不能将原有 noop 当作已迁移执行。狩猎、FATE、假面狂欢、新人训练、金碟和 PvP 清单不遗漏。
7. **最后清退桥。** 只有全部目标按接管边界验收后，才移除运行库加载、输入桥、导航/绘制桥、桥专属设置和依赖打包。迁移期间持续保留未迁内容。
