# PT30 光球通道与 Reach 转场

MP 自有 `promeradar.pt30` 脚本负责区域 1283 的此 Boss，场地使用 `Pt30Arena` 的真实外缘与洞口。运动光球按分时轨迹胶囊参与规划，世界预览只显示真实位置的 4m 圆。

中央洞口是静态硬障碍，阻止寻路穿过。雷达和真实世界绘制使用场地边界的白色描边，显隐遵循各视图的区域总开关与脚本来源开关。

## 通道几何与余量

危险区注册时统一叠加用户 `DodgeDangerMargin`。PT30 通过 owner 请求将求解器 `HardSafetyMargin` 与 `ArenaSafetyMargin` 设为 0；真实场地相交检测和保守网格占用仍然有效，不修改其他脚本的默认值。停止脚本时释放该请求。

不能同时为脚本危险区、硬危险网格、场地网格重复追加同一余量：在 0.5m 网格下，膨胀会向格数取整，可能封死本来可走的窄通道。保留光球真实 4m、运动观测余量 0.15m 与弦高、用户危险余量；不以缩小球体、洞口或扇形解决导航失败。

目标时序规划的部分解是临时避难，必须按现有解的有效期重解。光球几何以不增加快照版本的方式更新，不能单靠版本变化触发重解，也不能将安全等待点当作已经完成 Reach 安全侧目标。非目标规划的安全避难点继续保留稳定等待策略。

## 移动连续性

后台求解可能每 0.1 秒选出不同的临时落脚点。已下发的时序路线必须从当前 GreenMove 路点按最新场地、障碍和危险时间窗重新验证；仍安全且不会错过等待期限、机制目标优先级不降低时，继续走完当前阶段。候选落脚点变化不能单独触发 MoveTo，也不能让候选的原地等待分支停止仍在执行的安全路线。更高优先级的新目标或实际不安全的剩余路线仍立即触发切换。

`NavigationContinuityRegression` 覆盖快照版本及候选落脚点连续变化、候选原地等待、等待结束期限、目标迁移和新增危险；复现用例在修复前下发 11 次，修复后下发 1 次，并验证新增危险会停止旧路线。这是执行层定向回归，不等同于完整游戏内机制验收。

宿主 PR 还必须实际加载含 `PromeRotation.GreenMoveSystem.GreenMoveArrival` 的构建。旧宿主仅检查当前位置进入路点容差时，跨帧越过小容差的中间点会反向追点；本轮曾出现 MP 下发计数连续数秒不变、角色在约 0.7m 内反复折返。回归直接调用编译引用的 PR 到达判定，验证中间点跨帧经过、精确终点保留、显式经过终点、侧向偏离与远距离位移边界。不能用 MP 热重载代替 PR 本体更新；更新 PR 后须用匹配引用重编译 MP，并核验运行中 PR 的 MVID 与文件一致。

## 移动光球期间的安全站位

11 月 18 日 12:45:42 ARR（build 14251465）与当天运行日志以 927 条技能效果的技能 ID 和序列号对齐。12:45:31.177 起的两秒里，角色累计移动 11.23 码，净位移约 0.23 码，HP 保持 120145。同期 `follow` 单帧耗时约 28–39ms。前一场 12:26:52 ARR 在 12:25:57 附近也有明显往返，两秒累计 17.40 码、净位移 1.14 码。12:46:15 文件只有 16 秒，未进入 PT30 战斗。随后保存的 13:12:33 ARR 有 1303 条技能效果匹配。13:12:01.863 起的两秒再次出现往返，累计移动 10.95 码、净位移 1.83 码。

按 12:45:42 ARR 的分时球位重建时，旧模型用约 100ms 的两点差估计角速度并外推十秒，网络位置修正会放大预测波动。录制 1102.1 秒附近，同一站位可以在原地等待、挪动半码和绕远之间反复切换。通用跟随还会用未来约 2.5 秒的光球预测过滤攻击位置。胶囊没有轮廓，原过滤会按包围盒排除攻击位，并在找不到落点时扫描场地。

光球角速度改用最近约 0.8 秒的观测，持续静止时恢复常驻圆。光球阶段暂时让出通用跟随。没有机制站位目标时，执行器同时验证原地等待和延后出发的路线，允许短时停在安全通道。撤离余量不足时出发，光球阶段结束便恢复跟随。

`arr-124542-moving-balls.json` 保存匿名化站位、插值球位和读条快照。`PT30 recorded moving balls safe refuge` 用真实解算器和下发逻辑验证五次可省去的移动，以及之后必须保留的一次撤离。ARR 插值用于离线对照，无法还原当时插件每帧接收的球位或 GreenMove 指令。游戏内效果需用新构建的实战录像确认。

## 光环、光球与半场刀叠加

11 月 18 日 16:20:29 ARR 与日志对齐后，确认角色跑至 `(-318.65, -306.26)` 后，在同一点停留约 5.5 秒，被 16:19:38.076 的 Grip（44927）命中。此前约两秒的持续跑动约为 8.5 码／秒。14–19 码光环在 16:19:34.196 判定；按保守窗口重建，约 16:19:34.31 才能进通道。以 6 码／秒在通道刚打开时仍有解，晚约半秒重搜得到 `NoTemporalPath`。

光球、光环和 Grip 同时预告时启用分段时序规划。第一段可站定等待，执行器保存后半段，并在通道开放时用最新快照复核地形和危险窗口后下发。光球阶段独立的安全站位等待不叠加到这条分段路线。

PT30 用约 0.8 秒的玩家位置窗口确认稳定或逐步增加的移速，加速时采用已观测的保守速度，求解和执行检查共用它。较快的观测最多保留 8 秒，角色切换、回放和移速模型变化会清掉旧观测。每两秒的 `[PT30]` 状态行记录 `planSpeed`。`arr-162029-halo-grip.json` 的离线测试从跑动轨迹得到 8.39 码／秒，验证等待、通道开放后续走，以及迟半秒重搜时恢复可达路线。

## 定向验证

`tests/Fixtures/PilgrimsTraverse30/merged-001823-passages.json` 保留原 MP 录像的 77、97、205 秒快照和源文件哈希。`Pt30PassageRegression` 调用真实 `SafeZoneSolver`，要求完整、非降级路线，终点落在 Reach 安全侧；以 10ms 采样整条路线、等待段及判定前终点停留，校验原场地、洞口和已外扩危险区。另验证目标部分解到期重解、普通避难点稳定性。

入口：`MasterPlayer.RegressionTests --filter=PT30 --keep-going`；公共移动缓存修改同时运行 `--filter="Navigation continuity"`。原录像定点对比可用 `--pt30-recording <MP录像> 77 97 205`，分别报告旧额外余量与当前脚本参数。

此验证重建原位置并检查新规划，不模拟实际走位、异步求解延迟或服务器位移执行；不能替代新一轮游戏内实测。
