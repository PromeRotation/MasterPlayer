# 快速开始

两条路线：**玩家**只需要装好、启用、会用；**AI 代理 / 开发者**要能构建、测试，并按录像修机制。

---

## 玩家

### 1. 安装

1. 先装好 XIVLauncherCN 与 **PromeRotation（PR）**，并能正常进游戏。
2. 把 `MasterPlayer.dll`、`MasterPlayer.MechanicRuntime.dll`、`PromeRotation.Scripting.dll` 放进
   ```
   %AppData%\XIVLauncherCN\pluginConfigs\PromeRotation\Plugins\MasterPlayer\
   ```
   自己编译时这一步自动完成（见下文「开发者」）。
3. 游戏内打开 PR 的插件管理器，启用 **PromeRadar**。列表里没有就点「刷新全部」。

### 2. 第一次使用

| 操作 | 方法 |
|---|---|
| 打开设置面板 | 聊天输入 `/prpr` |
| 开 / 关智能走位 | `/prpr ai on`、`/prpr ai off`，或点服务器信息栏的 `PromeRadar AI` |
| 开始 / 停止录制 | `/prpr rec` |
| 打开回放窗口 | `/prpr replay` |

推荐的初始设置：

1. 「总览」打开**雷达悬浮窗**和**真实世界绘制**，先看清危险区。
2. 「机制脚本」勾选要用的脚本（斗兽五盘、糖豆人、三个 ARR 地城），进入对应区域自动启动。
3. 确认绘制正确后再开**智能走位**。PR 本体的安全区自动移动开着时插件会让位，冲突时在「总览」点「关闭 PR 本体安全区自动移动」。

### 3. 遇到问题

- **没画出来**：看「诊断」页的危险区数量和运行中脚本；确认脚本已勾选、区域对得上。
- **躲错了或撞了**：用 ARR 录下那一把，把文件名和出问题的大概时间点发给开发者。新录像在
  `游戏目录\game\My Games\FINAL FANTASY XIV - A Realm Reborn\replay\autorenamed\`。
- **更新后报错**：PR 本体更新后插件必须重新编译。

### 2. 仓库地图

| 目录 | 内容 |
|---|---|
| `src/Core/` | 插件入口 `MasterPlayerPlugin.cs`、设置、IPC 集成 |
| `src/Spatial/` | 安全区：几何、注册表、快照、解算器（后台线程）、移动调度 |
| `src/Movement/` | 智能走位：通用躲避 `Dodge/`、跟随 `Follow/` |
| `src/Mechanics/` | 机制分发框架；`Host/` 为机制运行库宿主桥 |
| `src/Scripting/` | 脚本框架、可视化脚本 |
| `src/Replay/` | 插件自身的录制回放 |
| `src/UI/` | 雷达 `Radar/` 与各窗口 `Windows/` |
| `Presets/<区域>/` | **内置预设**：每个区域一个目录，含实现、数据与 `Entries/` 脚本入口（斗兽 `Crucible`、糖豆人 `Blunderville`、地城 `Dungeons`、示例 `Examples`） |
| `MechanicRuntime/` | 机制运行库（其他副本的机制模块，独立项目） |
| `tests/` | 回归程序与录像夹具（`tests/Fixtures/<区域>/`） |
| `tools/arr/` | ARR 录像解析脚本 |

### 3. 构建与测试

```powershell
dotnet build MasterPlayer.csproj -p:CI=true          # 只编译到仓库 bin\，不动游戏
dotnet run --project tests/MasterPlayer.RegressionTests.csproj -c Release -p:CI=true -- --keep-going
dotnet run --project tests/MasterPlayer.RegressionTests.csproj -c Release -p:CI=true -- --filter="Recorded B02"
dotnet build MasterPlayer.csproj -c Release           # 编译并直接部署到 PR 插件目录
```

- 本机的 PR 路径写在已忽略的 `Directory.Build.local.props`，详见 [README](../README.md#构建)。
- 全量回归有少量 Blunderville 场景依赖真实 CPU 时间，判断回归前先在改动前的提交上跑基线对比。
- **部署前先备份**插件目录里的 `MasterPlayer*.dll/.pdb`（加时间戳后缀），并以用户确认为准。

### 4. 修一个机制问题

```powershell
# 1. 找录像（新录像在游戏目录 replay\autorenamed\）并解码
python tools/arr/opcode_map.py --game "<游戏目录>\game" --arr "<录像>.dat"   # 该客户端版本首次需要
python tools/arr/arr_decode.py "<录像>.dat" --out analysis/<日期>/
```

2. 在解码结果里找到出问题的时间点，列出前后的读条、效果（`targetIds` 含玩家即被命中）、对象与玩家位置。
3. 找到负责的组件（技能 ID 在 `Presets/Crucible/Source/CrucibleEnums.cs` 或对应 spec 里搜）。
4. 裁一个匿名夹具到 `tests/Fixtures/<区域>/`，写一个能失败的模拟场景，参考 `tests/RecordedDodgeRefinementRegression.cs`、`tests/RecordedHigh1FeedbackRegression.cs`。
5. 修复到场景通过，跑全量回归对比基线，更新 spec，提交。

详细步骤与判读规则见 [ARR 解析与模拟流程](ARR解析与模拟流程.md)。
